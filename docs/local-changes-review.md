## 对照证据

- 400×220 合成照片，背景亮度从 105 渐变到 245，上下两行共 8 个笔画组合。固定阈值检出 2 个，附件拍照模式和整合后的拍照模式均检出 8 个。新增测试还覆盖相邻字符不粘连、低幅噪声、空白阴影、小图和透明背景。
- 附件的 `_adaptive_binarize` 实际使用 CLAHE 和局部均值阈值，不是注释声称的 Sauvola；整合后按实际算法描述。
- 附件字符表确实有 2500 个不同字符，但所谓频率前缀去重后只有 115 个。500 字的其余部分按笔画表补齐，不能据此声称“按频率排序、覆盖日常 80%”。保留其作为采样起步列表，不给覆盖率保证。
- 对附件 LaMa 的写回逻辑进行隔离测试：100×200 彩色背景 `(130,180,220)`（BGR），在 `[40:60,90:95]` 放置深色笔画并作为遮罩，用户选区为 `[35:65,85:115]`。把 `_get_session` 替换为占位对象，`_run_tile` 返回全白的理想纸面输出。最终仍改变笔画遮罩外 **1650** 个像素，其中 **1000** 个在选区外。问题来自把整个遮罩包围盒高斯模糊后写回，测试不需要真实模型就能复现。
- 附件 `_compute_tile_weight(512,512,全1遮罩)` 的首行权重全为零。位于整图最外侧的遮罩像素没有相邻块补权重，可能保留原笔画。
- 附件 `inpaint` 先转灰度，写回也由灰度复制成三通道；`inpaint_pil` 丢弃 alpha。它们与当前选区外像素一致、彩色纸张和透明度保留的约束冲突。
- 附件 `_inpaint_lama` 在模型缺失或任何异常时回退 NS，但前端仍显示 LaMa；目前不提供这种没有实际能力反馈的选项。

以上是对这版封装的判断，不代表 LaMa 模型本身不适合修复。真实模型推理、真实手机照片和倾斜/复杂纸面的效果未在本轮验证。

## 合入后的使用方式

手写档案 → 导入样本 → 切割字形 → 勾选“拍照模式”。该开关同时影响检测和保存时的纸面去阴影；保存失败保留候选、旧会话隔离等现有行为不变。去背景使用局部纸张估计和颜色差异，保留彩色笔画和已有透明度。粗涂抹、强纹理、反光、复杂阴影仍需人工检查。

手写档案 → 展开档案 → 生成补字采样页。下载的 HTML 无外部依赖，可在浏览器打印；每页最多 48 字，参考字与书写区分开。拍照时裁掉参考文字，核对候选后粘贴该页字序，TXT 每行对应一页。字符去重和过滤空白使用 Unicode 码点，HTML 中的档案名和字符会转义。
