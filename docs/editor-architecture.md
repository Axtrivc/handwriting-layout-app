# 编辑器职责与数据流

这次重构围绕四个行为约束，而不是按旧组件大小机械拆文件。

## 文档是唯一持久状态

`documentState.ts` 的 reducer 管理 project、revision、savedRevision、generation。
`useDocument.ts` 提供内容修改、更新页面、切页、替换工程和保存确认。

- 所有内容修改（包括手写档案）统一增加版本，更新未保存状态。
- 保存确认只确认当前快照的版本，不会清除后续编辑的未保存状态。
- 加载工程递增 generation，旧工程发出的异步修改不允许写入新工程。
- 内容修改使用最新 project 执行函数更新，避免异步请求拿旧数组覆盖新内容。
- 切页属于视图导航，不触发内容未保存提示。

`profileEdits.ts` 在提交时根据最新档案分配字形变体编号，已删除样本的结果不再写入。

## 工程导入与标注失败恢复

`projectValidation.ts` 在补全旧版默认值前验证所有已提供的字段，包括嵌套字形、样本、清除历史、重复 ID 和尺寸。格式损坏会给出字段路径，不再静默过滤掉损坏内容。仍支持缺少新字段的旧工程。

`useProjectFiles.ts` 负责读取、校验和解码工程资源（包括清除历史），全部通过后才替换文档。取消文件选择、图片损坏或拒绝丢弃未保存修改都会保留当前工程。图片导入与画布保持相同限制：单边最多 16384 像素、总计最多 6400 万像素。保存提示表示已生成 JSON 下载，不宣称操作系统已经写入磁盘。

字形保存返回明确成功结果；失败时保留候选、字符和批量文本。`glyphBatch.ts` 按阅读顺序生成带候选 ID 的保存计划，成功后只消费本次计划包含的候选。批量裁剪全部成功后统一提交，重试不会重复写入失败批次的前半部分。检测失败也保留已有标注。

标注窗口使用独立会话序号，关闭、打开其他样本或加载工程后，旧请求不再改变新窗口的忙碌状态和错误信息。OCR 的请求和结果使用同一候选顺序。

## 图片是派生资源

页面保存图片源，`useImageResource.ts` 负责解码和过期加载隔离。移除 pageId 对应图片的第二份可变状态，复制、加载和清除后不会再漏同步缓存。
`useGlyphImages.ts` 加载各档案字形，统一用 profileId:glyphId 标识，支持文本指定非活动档案。

## 清除是带确认的编辑事务

`useCleanup.ts` 管理选区、请求、比较原图和临时预览。应用预览才提交文档，取消不修改文档。
请求结束时核对页面、原背景和操作上下文；切页、换图或载入工程会作废旧结果。

## 编辑和导出使用同一绘制描述

`textScene.ts` 生成字体/字形节点以及整个文本对象的变换。
`TextObjectView.tsx` 用它呈现可交互的对象组；拖拽、选中和旋转作用于可见内容整体。
`offscreenRender.ts` 使用相同描述生成独立 Konva 场景，结束后销毁场景资源。

PNG、PDF、ZIP 都通过这条路径，从文档快照绘制，不截取正在缩放/平移的编辑画布，不带选区或提示覆盖层。
自然化使用项目已有对象种子，不再每次打开工程随机生成全局导出种子。
PDF 的像素倍率仅影响图片清晰度，不改变纸张尺寸。超出像素限制时报错，不尝试分配无限大的画布。

`useProjectExport.ts` 负责导出任务、进度、错误和互斥；PDF 操作显式 await，失败进入统一错误提示。
空白页也支持正常编辑和导出。

## 回归验证

- `node scripts/test_document.mjs`：版本、旧请求、并发内容更新、字形变体。
- `node scripts/test_editing.mjs`：撤销重做和选区边界。
- `node scripts/test_project_files.mjs`：损坏字段、无损保存加载、旧版迁移、默认值及稀疏/Unicode 批量标注。
- `scripts/test_project_files_ui.cjs`：模拟导入失败、取消、拒绝覆盖、尺寸限制、单项与整批保存重试、未标注候选保留、OCR 顺序、旧会话隔离及拖拽边界；此脚本仅需 Vite，API 响应在浏览器内模拟。
- `scripts/test_export_ui.cjs`：真实 Chromium 检查缩放平移不影响 PNG、倍率尺寸、复制页背景、档案未保存提示、旋转、稳定输出、PDF 纸张尺寸及空白页。
- `scripts/test_clean_ui.cjs`：清除预览、原图比较、应用/取消、撤销、选区调整及延迟请求隔离。

浏览器脚本需要已启动 API/Vite，且可通过 PLAYWRIGHT_MODULE 和 CHROMIUM_PATH 指定外部工具路径；配置示例见 cleanup-validation.md。
本次未新增运行依赖，也未更改项目 JSON 格式。

## 后续仍可改进

App 保留了页面/文本操作和字形标注界面的组装。大量字形解码的增量缓存、统一所有操作的撤销事务、超大工程导出内存控制仍值得继续设计。本轮验证不代表全仓库每一行都已完成审计，也不代替桌面平台和真实手写素材验收。
